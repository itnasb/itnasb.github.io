EntraKeeper Maintaining authenticated state during Burp Suite audit-only scans

Burp Suite Java Extension Playwright Entra ID Authenticated Scanning Session Management Montoya API

Summary

EntraKeeper is a Burp Suite Java extension built to keep audit-only scans authenticated when applications use Entra ID and rely on session cookies for authenticated state. In these applications, Burp can begin with a valid session, but that state eventually expires. Once it does, requests start failing, coverage drops, and scan results become less reliable.

The extension solves that by using Playwright to automate Burp Suite's built-in Chromium browser through the application's recorded login flow. It follows the Entra ID authentication sequence, returning to the application's landing page, and sends that traffic through Burp's proxy so Burp's cookie jar is updated with fresh session cookies.

The result is a more reliable way to maintain authenticated state during long-running audit-only scans against modern applications that depend on externally managed authentication and cookie-based sessions.

Project Status

This is a placeholder project for when I eventually rebuild the extension for public use.

The Problem

BurpSuite handles session state well during a crawl and audit scan, but scanning via a crawler results in reduced coverage. In contrast, a manually mapped audit-only scan can increase converage but session state for applications where authentication is performed via EntraID isn't maintained.

Applications that use Entra ID often complete authentication through a browser-based redirect flow and then issue one or more session cookies that the application uses to track authenticated state.

In an audit-only scan, those cookies may stay valid for minutes or for hours, but they eventually expire. Once that happens, requests start quietly failing unless the session is renewed.

That creates a few practical problems:

  • authenticated coverage drops mid-scan
  • stale cookies remain in circulation until something replaces them
  • requests start failing as the session ages out
  • scan results become less reliable
  • testers may not immediately realize the scan is no longer meaningfully authenticated

This eliminates the benefit of increased coverage that manual mapping and audit-only scanning provide.

A tester can manually open the browser and reauthenticate, renewing the cookies stored in BurpSuite's cookie jar. But if a session expires over night, or in other off-work hours, it's unlikely to be caught.

EntraKeeper exists in the gap between starting a manually mapped audit-only scan authenticated and keeping it authenticated. It treats session renewal as part of scan quality not just about convenience. It's about preserving coverage and keeping Burp operating against the authenticated application state the tester intended to assess.

It also reflects engineering work that matters in application security but doesn't always get highlighted: building the tooling needed to test modern applications well, not just using existing tools as-is.

Approach

EntraKeeper solves the problem by automating reauthentication, using Playwright to drive Burp Suite's built-in Chromium browser through the recorded login sequence and a user-provided starting URL. From there, it follows the required redirects through the Entra ID flow, lands back on the application, and ensures the resulting traffic passes through Burp's proxy.

This means Burp sees the authenticated traffic and updates its own cookie jar so stale cookies can be replaced with fresh ones during the scan.

Technical Workflow

The workflow looks like this: 

1. The user provides a starting URL and Burp recorded login sequence.
2. The extension launches Burp's Chromium browser through Playwright.
3. The automated browser follows the application's Entra ID authentication flow.
4. The last steps in the flow result in 
   4.1 The browser follows a redirection to the application authentication endpoint where session cookies are set 
   4.2 The browser follows a redirection to the application landing page.
5. The traffic is sent through Burp's proxy.
6. Burp observes the new authenticated traffic and updates its cookie jar.
7. Future audit requests can use the refreshed session cookies instead of stale ones.

To make that work, the extension attempts to identify Burp's Chromium browser path and active listening port automatically, while still allowing the user to configure either value manually when the automatic choice is wrong.

Burp still handles the proxy, cookie jar, and scanning. EntraKeeper simply renews authenticated state.

Tradeoffs and Current Limitations

The current version runs on a user-configurable timer. That works . . . Kind-of.

Refreshing on a schedule rather than when the session is actually no longer valid means it can fail to renew on time, or renew earlier than necessary, and in some applications that can create its own problems. If the login sequence doesn't also result in fresh XSRF tokens or other session-bound values, forcing a refresh too early can cause requests to fail sooner instead of later.

There are also environment-specific limitations. Automatically selecting Burp's active listener port works for straightforward setups, but it can be wrong when Burp is listening on more than one port. The current implementation is also focused on cookie-based session renewal and hasn't been tested against other modern authentication providers.

So the extension solves the immediate problem, but it doesn't pretend to solve every version of it yet.

Planned Improvements

The next major improvement is to move away from a timer-only model.

A better approach is to use Burp's Montoya API HTTPHandler method to detect when authenticated state has actually been lost. Instead of refreshing on a fixed schedule, the extension can watch for redirects back to login or other response patterns that suggest the session is no longer valid. Another option I plan to implement is inspired by Invicti's implementation of form based authentication, user-defined keyword detection, where the tester provides response text that signals logout, timeout, or forced reauthentication.

A future version will also support bearer tokens and other session-tied headers. The plan is to let the user define a comma-separated list of headers that should be tracked alongside cookies. That may require allowing the user to send multiple URLs to the extension for different session related purposes so the extension can reauthenticate, reach the right endpoint, and capture fresh token-bearing requests or headers.

It also needs testing against other identity providers such as Okta.

Autovader Influence

This project wouldn't have been written without the Autovader extension.

Autovader already solved the problem of launching and automating Burp Suite's built-in browser with Playwright. That work directly inspired EntraKeeper and provided the model for browser launching, browser-driven navigation, and automatic discovery of the Burp Chromium browser path with a manual fallback when discovery fails.
