Detecting Hidden Textarea XSS: Detecting Scanner-Missed Reflections with a Custom Burp BCheck

Burp Suite BCheck XSS Cross-site scripting Web Security Testing

Summary

[TEMPLATE] Burp Suite Professional often misses reflected XSS when user input is injected into an existing <textarea> because tags inside a textarea are treated as text. This BCheck detects that scenario by injecting a closing </textarea> marker followed by multiple XSS payloads and confirming reflection into a context where HTML is parsed.

Technical Analysis

[TEMPLATE] Developers often assume textarea content is “safe” because the browser renders tags inside <textarea> as literal text. If the application reflects input without proper HTML entity encoding, an attacker can break out using </textarea> and the browser resumes normal HTML parsing—enabling script execution.

Detection Strategy

  • [TEMPLATE] Generate a random marker to reliably identify reflections.
  • Inject a closing </textarea> breakout plus multiple payload types (e.g., <img onerror>, <script>).
  • Confirm the marker appears inside an existing textarea element (not just anywhere in the response).
  • Validate the response Content-Type is a markup type that the browser will parse/render (HTML/SVG/XML-ish) before reporting an issue.

Demonstration Lab

[TEMPLATE] This check is paired with an intentionally vulnerable training endpoint so analysts can practice identifying textarea breakout reflections that automated scanners often miss.

BCheck Implementation

[TEMPLATE] Below is the compact BCheck implementation with inline comments explaining the detection logic. 



# This BCheck was written to detect Cross-site Scripting in Textarea HTML elements that Burp Suite Professional often misses during scans.
# Tags included in textarea elements are treated as text even if they are not handled safely by application code. If an XSS
# proof-of-concept is prepended with a closing textarea, and the application is echoing back unencoded user controlled input,
# it will allow for cross-site scripting that Burp Suite Professional will usually miss.


metadata:
  language: v2-beta
  name: "Reflected XSS in Textarea Context"
  description: "Version 0.1 Detects reflected textarea breakout XSS using </textarea> + payload and validates textarea context"
  author: "asdfa"
  tags: "active", "xss", "reflected", "textarea"

define:
rand6 = {random_str\(6\)}

breakout = `{rand6}</textarea>`
payload_img = `{breakout}<img src=1 onerror=alert(1)>`
payload_script = `{breakout}<script>alert(1)</script>`

# Encode ONLY < and > for reporting
payload_img_enc = {regex_replace(regex_replace(payload_img, "<", "&lt;"), ">", "&gt;")}
payload_script_enc = {regex_replace(regex_replace(payload_script, "<", "&lt;"), ">", "&gt;")}

# Checking for opening <textarea ...> that is not closed until injected </textarea> appears
textarea_breakout_regex = `(?s)<textarea[^>]*>(?:(?!</textarea>).)*?{rand6}</textarea>`

# MIME types where HTML/SVG/XML are parsed/rendered (case-insensitive)
ct_allows_markup_regex = `(?i)\bcontent-type:\s*(text/html|application/xhtml\+xml|image/svg\+xml|application/xml|text/xml)\b`

given query or body insertion point then

	# xss via img tag
	send payload:
	appending: {payload_img}

	if ({latest.response.body} matches {textarea_breakout_regex} and
		{latest.response.headers} matches {ct_allows_markup_regex}) then
		report issue:
		severity: high
		confidence: certain
		detail: `A reflected cross-site scripting vulnerability was found in {insertion_point_name} parameter sent to the {request.url.path} endpoint. The payload {payload_img_enc} was injected into {insertion_point_name} and reflected unsanitized into a textarea element at {request.url.path}.`
		remediation: "Apply HTML entity encoding to user-controlled data before inserting into HTML contexts, including textarea elements."
	else

	# xss via script tag
	send payload:
	appending: {payload_script}

		if ({latest.response.body} matches {textarea_breakout_regex} and
		{latest.response.headers} matches {ct_allows_markup_regex}) then
			report issue:
			severity: high
			confidence: certain
			detail: `A reflected cross-site scripting vulnerability was found in {insertion_point_name} parameter sent to the {request.url.path} endpoint. The payload {payload_script_enc} was injected into {insertion_point_name} and reflected unsanitized into a textarea element at {request.url.path}.`
			remediation: "Apply HTML entity encoding to user-controlled data before inserting into HTML contexts, including textarea elements."
		end if
	end if

Real-World Relevance

  • [TEMPLATE] Apps that reflect user input into form fields or server-rendered templates.
  • Legacy frameworks or custom templating layers that do partial/incorrect encoding.
  • Endpoints that return HTML/SVG/XML content types where markup is parsed and scripts can execute.

[TEMPLATE] In these cases, generic scanner payloads can miss exploitable contexts without targeted breakout logic.
